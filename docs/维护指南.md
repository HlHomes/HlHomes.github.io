## 0. 三条命令

在项目目录 `D:\my_project` 下打开终端：

```bash
npm run dev      # 本地预览，改文件自动刷新 → http://localhost:4321
npm run build    # 推送前必须跑一遍，确保零报错
npm run check    # 类型检查（可选，但改了 .ts/.astro 建议跑）
```

`npm run dev` 启动后是常驻的，停止用 `astro dev stop`。

> **环境要求**：Node ≥ 22.12。当前用的是 Node 24（装在 `C:\Program Files\nodejs`）。如果终端里 `node -v` 显示的是 20.x，说明命中了旧的便携版 Node，先执行 `node -e "console.log(process.execPath)"` 看用的是哪一个。

## 1. 心智模型：想改什么就动哪个文件

整个网站只有三类内容来源。**记住这张表，90% 的维护问题都能自己解决。**

| 内容类型 | 存放形式 | 位置 |
| --- | --- | --- |
| 个人资料（姓名、定位、学校/单位、简介、社交、技能） | TypeScript 常量 | `src/config.ts` |
| 教育背景 | YAML 数据文件 | `src/data/education.yaml` |
| 实习经历 + 工作经历 | YAML 数据文件（同一个） | `src/data/experience.yaml` |
| 论文、项目 | YAML 数据文件 | `src/data/publications.yaml`、`projects.yaml` |
| 长文（博客） | Markdown 文件 | `src/content/blog/{zh,en}/*.md` |
| 界面文案（导航名、按钮字） | 中英词典 | `src/i18n/ui.ts` |
| 外观（配色、字体、特效） | CSS | `src/styles/global.css` |

首页板块从上到下的顺序（在 `src/components/views/HomeView.astro` 里，调整顺序就是调整那些 `<section>` 的先后）：

```
关于我  →  教育背景  →  实习经历  →  工作经历  →  技能栈  →  精选论文  →  精选项目  →  最新文章
```

**没有数据的板块会自动隐藏**，不会留一块空白。比如现在还没有正式工作经历，「工作经历」板块就不显示。

页面与文件的对应关系：

| 网址 | 由谁生成 |
| --- | --- |
| `/` 和 `/en/` | `src/pages/index.astro` → `views/HomeView.astro` |
| `/publications` | `src/pages/publications.astro` → `views/PublicationsView.astro` |
| `/projects` | `src/pages/projects.astro` → `views/ProjectsView.astro` |
| `/blog` | `src/pages/blog/index.astro` → `views/BlogListView.astro` |
| `/blog/文章名` | `src/pages/blog/[...id].astro` → `layouts/PostLayout.astro` |
| 404 页 | `src/pages/404.astro` |

**一个重要约定**：`src/pages/` 下的文件都是「薄包装」，只有几行，真正的页面内容在 `src/components/views/` 里。这样中文页和英文页共用同一份代码，**改样式只需改一处，不会两边改出差异**。

## 2. 日常维护（高频）

### 2.1 改个人资料

**只需编辑 `src/config.ts`。** 这是全站唯一信息源。

```ts
export const PROFILE = {
  name: { zh: '贺磊', en: 'Lei He' },               // 侧栏显示的名字
  tagline: {                                        // 名字下面那行小字
    zh: '算法工程师 · 视觉 / 大模型应用 / 搜广推 / Agent',
    en: 'Algorithm Engineer · Vision / LLM Apps / RecSys / Agent',
  },
  affiliations: [                                   // 侧栏的学校与单位，按顺序显示
    { zh: '西南交通大学 · 人工智能硕士在读', en: 'M.Eng. in AI · Southwest Jiaotong University' },
    { zh: '阶跃星辰 · AIGC 算法实习生',      en: 'AIGC Algorithm Intern · StepFun' },
  ],
  bio: {                                            // 首页「关于我」正文
    zh: '我是西南交通大学人工智能硕士在读……',
    en: "I am a master's student……",
  },
  location: { zh: '四川成都', en: 'Chengdu, China' }, // 侧栏最后一行
  avatar: '/avatar.svg',                            // 头像路径，见 2.7
  authorAliases: ['贺磊', 'Lei He', 'He Lei'],       // 论文里你的署名，命中则自动加粗
};
```

侧栏从上到下就是：头像 → `name` → `tagline` → `affiliations` 各条 → `location`。

> **`tagline` 别写太长。** 侧栏只有 224px 宽，超过约 30 个汉字会折成很多行、把导航挤下去。你简历里「求职意向」有四个岗位方向，全文照搬会太挤，所以压缩成了 `视觉 / 大模型应用 / 搜广推 / Agent`。
>
> **换单位或毕业后**只改 `affiliations` 数组：加一条多显示一行，删一条少一行，不用动别的地方。

**社交链接**：把 `url` 填上就显示，**留空字符串就自动隐藏**，不用删整条。

```ts
export const SOCIALS = [
  { label: 'GitHub', url: 'https://github.com/HlHomes', icon: 'github' },
  { label: 'Email',  url: 'mailto:1601339895@qq.com',    icon: 'mail'   },
  { label: '知乎',    url: 'https://www.zhihu.com/…',      icon: 'zhihu'  },
  { label: 'Google Scholar', url: '', icon: 'scholar' },                    // 留空 = 隐藏
];
```

> **邮箱必须带 `mailto:` 前缀。** 只写 `1601339895@qq.com` 会被当成相对路径，点击后跳到 404。
>
> 邮箱写在公开网页上会被爬虫收集。如果开始收到垃圾邮件，把这条的 `url` 改成 `''` 就能立刻隐藏。

**技能栈**：分组显示，组名要中英各一份。

```ts
export const SKILLS = [
  {
    group: { zh: '研究方向', en: 'Research' },
    items: ['Image Restoration', 'Low-Level Vision', 'Face Recognition'],
  },
  {
    group: { zh: '大模型与 AIGC', en: 'LLM & AIGC' },
    items: ['LoRA / QLoRA', 'GPTQ / AWQ', 'vLLM', 'RAG'],
  },
  // 想加一组，照抄上面的结构追加即可；想删一组，整块删掉
];
```

**首页各板块显示几条**：

```ts
export const HOME_LIMITS = {
  publications: 3,   // 首页「精选论文」最多显示 3 条
  projects: 3,
  posts: 3,
};
```

> 首页只显示标了 `featured: true` 的论文和项目。想让某条上首页，去 YAML 里给它加这个标记。

### 2.2 改教育背景

编辑 `src/data/education.yaml`。**每条必须有唯一的 `id`**，页面按 `start` 倒序自动排列，你不用管顺序。

```yaml
- id: swjtu-master                            # 唯一标识，不显示在页面上
  school:
    zh: 西南交通大学
    en: Southwest Jiaotong University
  badge: '211'                                # 学校后面的小标签；不要就删掉整行
  degree:
    zh: 硕士
    en: Master's
  major:
    zh: 人工智能
    en: Artificial Intelligence
  start: '2024-09'
  end: '2027-06'                              # 在读中也照实写预计毕业时间
  highlights:                                 # 要点列表；不要就删掉整个 highlights 段
    zh:
      - 专业前 5%，研究方向：Low-Level 图像处理
      - 主修课程：人工智能与机器学习、数理统计、矩阵分析、计算机视觉
    en:
      - Top 5% of programme. Research on low-level vision.
      - Coursework — Machine Learning, Mathematical Statistics, Matrix Analysis, Computer Vision.
```

**注意 `start` / `end` 必须加引号**（写成 `'2024-09'`）。不加引号 YAML 会把它当数字运算，解析出错。

### 2.3 改实习经历与工作经历

**两者共用 `src/data/experience.yaml` 一个文件**，靠 `kind` 字段区分显示到哪个板块：

| `kind` 的值 | 显示在 |
| --- | --- |
| `internship` | 首页「实习经历」板块 |
| `work` | 首页「工作经历」板块 |

```yaml
- id: stepfun-2026                            # 唯一标识
  kind: internship                            # internship 或 work
  company:
    zh: 上海阶跃星辰智能科技股份有限公司
    en: StepFun
  role:
    zh: AIGC 算法实习生
    en: AIGC Algorithm Intern
  location:                                   # 可选；不要就删掉整段
    zh: 成都
    en: Chengdu
  start: '2026-05'
  end: ''                                     # 留空字符串 = 显示「至今」
```

**关于「只写公司和时间」**：不写 `highlights` 段，卡片就只显示公司、职位、地点和时间。当前两条实习就是这样。想给某条补上工作要点，加一个 `highlights` 段即可（格式与教育背景相同），文件里有注释掉的示例可以直接抄。

**关于「工作经历」板块**：目前还没有正式工作（`kind: work` 的记录为 0 条），所以该板块**自动隐藏**，首页不会留一块空白。毕业入职后，在这个文件里加一条 `kind: work` 的记录，板块就会自动出现——不用改任何代码。文件末尾有一段注释好的模板，取消注释填写即可。

**换工作 / 实习转正时记得同步两处**：

1. `src/data/experience.yaml` — 加新记录，把旧记录的 `end` 从 `''` 改成实际离职月份
2. `src/config.ts` 的 `PROFILE.affiliations` — 侧栏显示的当前单位

### 2.4 发一篇博客文章

**第 1 步**：在 `src/content/blog/zh/` 下新建一个 `.md` 文件。**文件名就是网址**，所以用英文小写加连字符，比如 `attention-is-all-you-need.md` → `/blog/attention-is-all-you-need`。

**第 2 步**：文件开头写 frontmatter（那对 `---` 之间的部分），然后正文用 Markdown。

```markdown
---
title: 文章标题
description: 一句话摘要，显示在列表页和搜索结果里
pubDate: 2026-07-29
lang: zh
tags:
  - Image Restoration
  - 笔记
---

正文从这里开始。

## 二级标题会自动进目录

支持行内公式 $y = (x \otimes k)\downarrow_s + n$ 和块级公式：

$$
\mathcal{L} = \frac{1}{N}\sum_{i=1}^{N}\|\hat{x}_i - x_i\|_2^2
$$

也支持代码高亮：

```python
def forward(self, x):
    return self.net(x)
```
```

**frontmatter 字段说明**：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `description` | 是 | 摘要，列表页显示 |
| `pubDate` | 是 | 发布日期，格式 `2026-07-29` |
| `lang` | 是 | `zh` 或 `en`，**必须与所在目录一致** |
| `tags` | 否 | 标签数组，随便写，不用提前注册 |
| `draft` | 否 | `true` 则只在本地可见，不会上线 |
| `updatedDate` | 否 | 更新日期，填了会在文章页额外显示 |
| `translationKey` | 否 | 中英两版填相同值，读者切换语言时直接跳到译文 |

**关于双语**：

- 只写中文完全可以。英文版读者切到 `/en/blog` 时看不到这篇，不会报错。
- 想做双语：在 `src/content/blog/en/` 建同名文件，`lang` 改成 `en`，两个文件都加同一个 `translationKey`（值随便，比如 `my-post-2026`）。这样文章页的语言切换按钮会直接跳到对方；**没有译文时会自动回落到博客列表页，不会出现 404**。

**第 3 步**：`npm run dev` 看效果 → `npm run build` 确认无报错 → 推送。

> 写作期间加 `draft: true`，本地能看、线上不显示。写完删掉这一行再推送。

### 2.5 加一篇论文或专利

编辑 `src/data/publications.yaml`，追加一条记录。**每条必须有唯一的 `id`**（自己起个短名，别重复即可）。

```yaml
- id: my-cvpr-2026                          # 唯一标识，不显示在页面上
  title: 'Degradation-Aware Prompting for Image Restoration'
  authors:                                   # 顺序即显示顺序
    - Zhang Wei
    - Helei                                  # 命中 authorAliases 会自动加粗
    - Li Ming
  venue: CVPR                                # 会议/期刊名
  year: 2026
  type: conference                           # 见下表
  note:                                      # 可选，显示为小徽章
    zh: 口头报告
    en: Oral
  featured: true                             # true = 同时出现在首页
  links:                                     # 不需要的字段整行删掉，别留空
    pdf: https://arxiv.org/pdf/xxxx.pdf
    code: https://github.com/HlHomes/xxx
    doi: https://doi.org/10.xxxx/yyyy
    bibtex: https://example.com/cite.bib
```

`type` 可选值：

| 值 | 含义 |
| --- | --- |
| `conference` | 会议论文 |
| `journal` | 期刊论文 |
| `preprint` | 预印本（如 arXiv） |
| `patent` | 专利 |

**排序是自动的**：按 `year` 倒序，论文页还会自动按年份分组，你不用操心顺序。

**没有链接的记录**这样写：

```yaml
  links: {}
```

**删除示例数据**：初始的三条记录带 `placeholder: true`，页面上会显示「示例数据，请替换」的徽章。换成真实记录后，把这一行删掉，徽章就消失了。

### 2.6 加一个项目

编辑 `src/data/projects.yaml`。结构与论文类似，但 **`description` 必须中英各一份**。

```yaml
- id: my-project                             # 唯一标识
  name: DACG-IR
  description:
    zh: 一句话说清这个项目做什么。
    en: One sentence on what this project does.
  tags:                                      # 显示为小标签
    - Image Restoration
    - PyTorch
  year: 2025
  stars: 7                                   # 可选，显示为 ★ 7；不想显示就删掉这行

  links:                                     # 不需要的整行删掉
    repo: https://github.com/HlHomes/xxx
    demo: https://xxx.github.io
    paper: https://arxiv.org/abs/xxxx
```

项目卡片在宽屏下是两列，鼠标悬停会轻微上浮并有柔光。

## 3. 调整标签

网站里有**四种不同的标签**，来源完全不同，改的地方也不同：

| 你看到的标签 | 来源 | 怎么改 |
| --- | --- | --- |
| 技能栈里的标签（PyTorch、vLLM…） | `src/config.ts` 的 `SKILLS` | 改数组元素；整组不要了就删掉整块 |
| 项目卡片上的标签 | `src/data/projects.yaml` 每条的 `tags` | 改数组；不要标签就删掉 `tags` 整段 |
| 文章的标签 | 每篇 `.md` 的 frontmatter `tags` | 改数组；不要就删掉 `tags` 整段 |
| 论文上的「在投 / 已授权」徽章 | `src/data/publications.yaml` 的 `note` | 改中英文案；不要就删掉 `note` 整段 |
| 学校后面的「211」徽章 | `src/data/education.yaml` 的 `badge` | 改成 `985` 之类；不要就删掉整行 |

**关键点：标签不需要提前注册。** 直接在 YAML 或 frontmatter 里写新词就会出现，删掉就消失，没有「标签总表」要同步维护。

> 目前标签只用于展示，点击不会筛选。如果以后想要「点标签筛选文章」的功能，需要新增一组动态路由页面，属于开发任务，不在日常维护范围内。

## 4. 增删栏目（导航项）

**先区分两个概念，改法完全不同：**

| | 首页板块 | 导航栏目 |
| --- | --- | --- |
| 是什么 | 首页上的一段区块（关于我、教育背景、实习经历…） | 侧栏导航里的一项 + 一个独立的二级页面 |
| 有哪些 | 关于我、教育背景、实习经历、工作经历、技能栈、精选论文、精选项目、最新文章 | 关于、论文、项目、博客 |
| 怎么调顺序 | 改 `HomeView.astro` 里 `<section>` 的先后 | 改 `Sidebar.astro` 里 `navItems` 的先后 |
| 怎么隐藏 | 删掉对应的 `<section>` 整块（或把数据清空，会自动隐藏） | 见下面 4.2 |

### 4.0 调整首页板块的顺序或显隐

打开 `src/components/views/HomeView.astro`，每个板块就是一个 `<section class="reveal">…</section>`。

- **调顺序**：把整个 `<section>` 块上下移动即可
- **临时隐藏**：把该块的数据清空（比如删掉 `education.yaml` 里所有记录），板块会自动消失
- **彻底移除**：删掉那个 `<section>` 块，以及文件顶部对应的 `getCollection(...)` 查询和组件导入

改完跑 `npm run build`，有漏删的引用会直接报错并指出行号。

### 4.1 只改栏目名字（最简单）

比如把「项目」改叫「作品」：编辑 `src/i18n/ui.ts`，**两种语言都要改**：

```ts
export const ui = {
  zh: {

## 5. 外观与特效

### 5.1 换配色

**只改 `src/styles/global.css` 里的两个块**，全站颜色都指向这些变量，改一个值整站跟着变。

```css
@theme {
  --color-canvas: oklch(0.99 0.002 90);    /* 页面背景 */
  --color-surface: oklch(0.972 0.003 90);  /* 卡片背景 */
  --color-ink: oklch(0.25 0.01 260);       /* 正文文字 */
  --color-subtle: oklch(0.55 0.012 260);   /* 次要文字 */
  --color-line: oklch(0.9 0.005 260);      /* 分割线、边框 */
  --color-brand: oklch(0.5 0.15 258);      /* 强调色：链接、高亮 */
  --color-brand-soft: oklch(0.955 0.022 258); /* 强调色的浅色版：徽章底、光晕 */
}

html.dark {
  /* 深色模式的同名变量，结构完全一样 */
  --color-brand: oklch(0.76 0.13 258);
  /* … */
}
```

**颜色格式是 `oklch(亮度 彩度 色相)`**：

| 参数 | 范围 | 调整效果 |
| --- | --- | --- |
| 亮度 | `0`（黑）～ `1`（白） | 调明暗 |
| 彩度 | `0`（灰）～ `0.37` | 调鲜艳程度，`0.15` 已经比较饱和 |
| 色相 | `0`～`360` | 换颜色，见下表 |

常用色相值：`0` 红 · `30` 橙 · `90` 黄 · `145` 绿 · `195` 青 · `258` 蓝 · `290` 紫 · `350` 粉

**换强调色的例子**——只改色相，明暗关系自动保持协调：

```css
/* 换成青绿色 */
@theme    { --color-brand: oklch(0.5  0.15 195); --color-brand-soft: oklch(0.955 0.022 195); }
html.dark { --color-brand: oklch(0.76 0.13 195); }
```

> **深浅两套都要改**，否则深色模式下颜色会和浅色模式不搭。
>
> 不习惯 oklch 也可以直接写 `#3b82f6` 这种十六进制，但 oklch 换色相时更不容易翻车（不会出现某些颜色突然变脏或变暗）。

### 5.2 换字体

同样在 `global.css` 的 `@theme` 里：

```css
--font-sans:
  ui-sans-serif, system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue',
  'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', 'Source Han Sans SC', sans-serif;
```

**顺序有讲究**：拉丁字体放前面，中文字体放后面。浏览器会用前面的字体渲染英文，中文自动回落到后面的 `PingFang SC`（macOS）/ `Microsoft YaHei`（Windows）。

> **不要引入 Google Fonts 等外部字体服务。** 当前用的全是系统自带字体，零网络请求。外链字体在国内网络下可能阻塞首屏渲染，白屏好几秒——这会直接破坏「随时随地能访问」这个需求。
>
> 真要用自定义字体，把字体文件放进 `public/fonts/`，在 CSS 里用 `@font-face` 本地引用，并且**务必做中文子集化**（完整中文字体动辄 10 MB 以上）。

### 5.3 特效清单与开关

所有特效都是**纯 CSS，不加载任何运行时 JavaScript**，不影响页面加载速度。定义集中在 `src/styles/global.css` 文件末尾那一段注释之后。

| 特效 | 效果 | 定义位置 | 作用在哪 |
| --- | --- | --- | --- |
| 滚动淡入上浮 | 区块进入视口时淡入并上移 | `global.css` 的 `.reveal` | 各页面的 `class="reveal"` |
| 顶部柔光 | 页面顶部两团柔和光晕 | `global.css` 的 `.page-glow` | `BaseLayout.astro` |
| 头像柔光环 | 头像下方淡淡的品牌色投影 | `global.css` 的 `.avatar-glow` | `Sidebar.astro` |
| 渐隐分割线 | 标题下的细线向右淡出 | `global.css` 的 `.rule-fade` | `SectionHeading.astro` |
| 下划线展开 | 链接悬停时下划线从左生长 | `global.css` 的 `.link-underline` | 侧栏社交链接、页脚等 |
| 卡片悬停上浮 | 项目卡片微微抬起并发光 | `ProjectCard.astro` 的 class | 项目卡片 |
| 姓名渐变 | 侧栏名字用渐变色填充 | `Sidebar.astro` 的 class | 侧栏姓名 |
| 导航指示条 | 当前栏目左侧短横线变长变色 | `Sidebar.astro` 的 class | 侧栏导航 |
| 细滚动条 | 更细、圆角的滚动条 | `global.css` 的 `::-webkit-scrollbar` | 全局 |

**调整某个特效**：

```css
/* 淡入更慢、位移更大 */
.reveal { /* 在 @supports 块里 */ }
@keyframes reveal-rise {
  from { opacity: 0; transform: translateY(28px); }   /* 14px → 28px */
  to   { opacity: 1; transform: none; }
}
/* 动画范围：数值越大，动画持续越久 */
animation-range: entry 0% entry 85%;   /* 改成 entry 0% entry 50% 会更快完成 */
```

```css
/* 光晕更明显 / 更淡 */
.page-glow { opacity: 0.75; }          /* 调这个值，0 = 完全关闭 */
html.dark .page-glow { opacity: 0.45; }
```

**关掉单个特效**：把模板里对应的 class 删掉即可。比如不要滚动淡入，就把各 `views/*.astro` 里的 `class="reveal"` 删掉（或改成 `class=""`）。CSS 留着不影响任何功能。

**关掉全部特效**：删掉 `global.css` 里 `视觉特效` 注释之后的所有内容，再删掉模板里的 `reveal` / `page-glow` / `avatar-glow` / `rule-fade` / `link-underline` 这些 class。网站功能完全不受影响。

**两个已经内置的贴心处理，不要删**：

- 系统开启「减弱动态效果」时，所有动画自动关闭（`prefers-reduced-motion` 那段）。这是无障碍要求。
- 浏览器不支持滚动驱动动画时（如部分 Firefox 版本），内容直接显示最终状态，不会一片空白（`@supports` 那层判断）。

### 5.4 调整布局宽度

编辑 `src/layouts/BaseLayout.astro`：

```astro
<div class="... mx-auto flex min-h-screen max-w-6xl flex-col px-5 sm:px-8 lg:flex-row lg:gap-14">
```

| 想要的效果 | 改法 |
| --- | --- |
| 整体更宽 | `max-w-6xl` → `max-w-7xl`（1152px → 1280px） |
| 整体更窄 | `max-w-6xl` → `max-w-5xl`（→ 1024px） |
| 侧栏更宽 | `Sidebar.astro` 里 `lg:w-56` → `lg:w-64` |
| 侧栏与正文间距 | `lg:gap-14` 改成 `lg:gap-10` 或 `lg:gap-20` |

**文章正文宽度**单独控制，在 `src/layouts/PostLayout.astro`：

```astro
<div class="prose max-w-[70ch]">
```

`70ch` 约等于 70 个字符宽。**不建议超过 80ch**——行太长，眼睛回行时容易串行，可读性明显下降。

> 侧栏在宽度 ≥ 1024px 时固定吸顶（滚动时不动），小于这个宽度自动变成页面顶部的横条。断点由 Tailwind 的 `lg:` 前缀控制。

## 8. 故障排查

### 构建失败

| 报错关键词 | 原因 | 解决 |
| --- | --- | --- |
| `is not supported by Astro` | Node 版本低于 22.12 | 确认 `node -v`，见第 0 节 |
| `Invalid frontmatter` / `expected date` | 日期格式错 | 必须 `2026-07-29`，不能写 `2026/7/29` |
| `bad indentation` / `unexpected token` | YAML 缩进错 | **只能用空格，不能用 Tab**；同级项缩进必须一致 |
| `Cannot find module './xxx'` | 删文件后有残留引用 | 报错会指出文件和行号，照着删掉那行导入 |
| `Property 'xxx' is missing` | `ui.ts` 里中英键不一致 | 补齐缺的那个键 |
| `Duplicate id` | YAML 里 `id` 重复 | 改成不重复的 |

### 页面表现异常

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 新文章不显示 | frontmatter 有 `draft: true`，或 `lang` 与目录不匹配 | 删掉 `draft`，检查 `lang` |
| 公式显示成原始的 `$...$` | 公式语法写错，或用了 KaTeX 不支持的命令 | 到 <https://katex.org/docs/supported> 查 |
| 样式全丢、页面变纯文本 | 极可能是 Pages 的 Source 设置被改了 | 仓库 Settings → Pages → Source 必须是 **GitHub Actions** |
| 改了内容但线上没变 | 部署还没跑完，或浏览器缓存 | 看 Actions 状态；然后 Ctrl+Shift+R 强制刷新 |
| 深色模式刷新时闪一下白 | `BaseLayout.astro` 里 `<head>` 的内联脚本被改动 | 那段脚本必须带 `is:inline` 且留在 `<head>`，不能移到 `<body>` |
| 滚动淡入没效果 | 浏览器不支持滚动驱动动画 | 属于正常降级，内容会直接显示，无需处理 |

### 本地调试技巧

```bash
npm run dev                    # 改文件自动刷新，最快的迭代方式
npm run build && npm run preview   # 预览真实构建产物（更接近线上）
npm run check                  # 类型检查，能提前发现 ui.ts 键不齐等问题
```

## 9. 禁忌清单

这几条踩了会比较麻烦，单独列出来。

| 不要做 | 为什么 |
| --- | --- |
| **不要改仓库名** | 必须是 `HlHomes.github.io`，GitHub 才把它当「用户主页站点」并给根路径。改名后站点变成子路径，还得去 `astro.config.mjs` 补 `base` 并修所有内部链接 |
| **不要引入外部 CDN 资源** | Google Fonts、jsdelivr、unpkg 在国内网络下可能阻塞首屏。要用什么库就装 npm 包，让构建产出本地文件 |
| **不要删 `package-lock.json`** | 部署用的 `withastro/action` 靠它判断包管理器，删了 CI 会失败 |
| **改站点域名要改两处** | `astro.config.mjs` 的 `site` 和 `src/config.ts` 的 `SITE.url` 必须一致，否则 sitemap 和 RSS 里的链接指错 |
| **YAML 里不要用 Tab** | YAML 规范只认空格，用 Tab 直接解析失败 |
| **不要把 `<head>` 里那段主题脚本改成普通 `<script>`** | 去掉 `is:inline` 会让它变成延迟加载的模块，刷新页面就会闪白 |
| **不要在组件里写死界面文案** | 会导致中英文不一致，且以后改文案要满项目找。统一放 `src/i18n/ui.ts` |
| **不要提交敏感信息** | 这是公开仓库，任何人可见。简历原件（`.pdf` / `.doc` / `.docx`）已在 `.gitignore` 里全局忽略，因为里面有手机号。**不要为了做「简历下载」而把原件放进 `public/`**——那等于把手机号公开到互联网。真要提供下载，先导出一份删掉手机号的版本 |
| **邮箱要带 `mailto:`** | `SOCIALS` 里只写邮箱地址会被当成相对路径，点击跳 404。另外公开邮箱会被爬虫收集，介意就把 `url` 改成 `''` 隐藏 |
| **YAML 的日期要加引号** | `start: '2024-09'` 必须带引号，不加引号会被当成数字表达式解析失败 |
